## 4. Bugs critiques découverts en cours de route (page dossier.php cassée)

En testant le module Biologie, un test sur la patiente CHAHID MALIKA (N°PAT 8899, sans ordonnance en cours) a révélé que sa page `dossier.php` était cassée : horloge bloquée à `--:--:--`, compteur RDV absent, section Ordonnance vide.

**Cause commune aux deux bugs trouvés** : plusieurs variables PHP n'étaient initialisées qu'à l'intérieur du bloc `if ($ordCourante):` (lignes 573–1286), alors qu'elles étaient utilisées plus loin dans la page **sans condition**. Pour un patient sans ordonnance en cours, ces variables restaient indéfinies → PHP émettait un Warning contenant du HTML brut (`<br />`, `<b>`) → ce texte s'injectait directement dans une valeur d'attribut HTML ou une chaîne JavaScript → ça cassait le parsing de tout le script qui suivait sur la page.

**Méthode de diagnostic** : récupération du HTML réellement généré par le serveur (`curl` vers la page, plutôt que de chercher dans le fichier source) pour faire correspondre les numéros de ligne signalés par la console du navigateur — indispensable car ces numéros se réfèrent au rendu final, qui se décale selon les données du patient.

**Bug 1 — `$rdvFuturVal`** (champ date de la popup "RDV prochain", ligne ~2445) : initialisation déplacée avant le `if ($ordCourante)`, au lieu de seulement à l'intérieur.

**Bug 2 — `$heureVisite`** (heure pré-remplie dans un bloc `<script>`, ligne ~2157) : même cause exacte, même correctif (initialisation à `''` déplacée avant le bloc conditionnel).

Les deux corrections suivent le même principe : une seule ligne déplacée, aucune autre logique touchée, donc risque de régression minimal.

**Fausse alerte au passage** : après ces deux corrections, le thème visuel a semblé totalement disparu (page en clair/sans couleur). Cause réelle : tests effectués en navigation privée + rechargements forcés répétés, qui ont fait perdre le cookie `logycab_theme`. Resélectionner le thème dans `parametres.php` a tout restauré — aucun fichier n'était cassé.

**Point de vigilance pour les prochaines sessions** : si une page de Logycab se comporte bizarrement uniquement pour certains patients (et pas d'autres), suspecter en priorité une variable initialisée seulement dans un bloc conditionnel (`if ($ordCourante)`, `if ($ordPrecedente)`, etc.) mais utilisée plus loin sans garde-fou. Il est possible que d'autres variables du même genre existent encore ailleurs dans `dossier.php` — pas vérifié de façon exhaustive.
